PROJECT OVERVIEW

让现场信息，
成为可读、可用的界面。

围绕钢结构制造现场的生产、库存、发运与报工，将多模块、高密度的业务信息，整理为一套清晰、一致的移动端体验。

设计重点落在用户每一次阅读与操作：先看到什么、如何判断状态、在哪里完成任务。以已有业务页面为基础，重组视觉层级，并建立可复用的组件语言。

CHALLENGE & OBJECTIVES

小屏幕，承载复杂现场。

将业务的复杂度留在系统里，把清晰的阅读顺序交给用户。

信息多，重点容易被淹没

编号、工序、数量与状态同时出现，阅读优先级不清晰。

建立层级对象 → 状态 → 明细 → 操作

状态多，判断需要反复确认

待处理、退回、催办等状态并存，需要稳定的视觉语义。

统一反馈颜色 + 文字，明确任务状态

模块多，界面语言不统一

跨业务切换时，卡片、筛选和按钮需要保持一致的使用逻辑。

沉淀组件统一结构，保留场景差异

DESIGN STRATEGY

让每一层信息，
都有自己的视觉权重。

先识别对象，再展开明细

构件编号成为卡片锚点；工号、件号与工序退为辅助信息，减少同一层级的视觉竞争。

让状态可识别，也可读

常规、提醒、异常采用统一语义色，并保留文字标签，避免只依赖颜色判断。

将高频操作放在稳定位置

筛选集中在列表上方；页面主操作固定于底部；确认面板再次呈现对象和工序。

图形看趋势，数字看细节

统计页通过选中态连接图表与数据，重量、件数、面积各自保留单位与口径。

KEY SCENARIOS

四个现场，同一种清晰。

以典型任务串联页面，用真实设计稿展示信息组织与视觉决策。

生产 / 车间管理

让产量、设备与任务各就其位。

场景问题

同一页面内既要掌握生产概况，也要进入具体构件任务。

设计处理

顶部汇总关键产量，工序数据与设备状态分组呈现；任务列表采用对象卡片，突出编号、当前工序和处理入口。

指标分层 对象卡片 操作核对

堆场 / 库存

从库存总量，逐层读到结构。

场景问题

重量、件数、趋势和库存构成需要并列查看，却不能混为一种数据。

设计处理

总览优先显示库存和出入库信息；分析页用图表呈现变化，选中态关联具体数值，分开标注重量与件数。

数据口径 图表选中态 作业与分析分区

发运 / 物流

把流转状态，放回任务上下文。

场景问题

发运单、运输状态与地点信息分散时，用户难以快速确认当前任务。

设计处理

列表突出单号与状态；详情页将线路、阶段进度与运输信息串联，底部保留明确的下一步操作。

单号优先 进度表达 信息核对

数据统计 / 报工

让数据阅读与现场填报更有条理。

场景问题

不同岗位关注点不同；密集字段与统计图表也需要各自的阅读节奏。

设计处理

组员工作台突出填报入口与任务，表单按作业信息和完成情况分组；统计页以周期和计量单位组织数据。

岗位入口 表单分组 周期与单位
