背景 · 01

原来：一张 Excel 管到底。

合同、交付、收款记在同一张台账里，市场、交付、财经各填一段，进度靠人去问。

信息散线索、客户、合同、单据分在不同表格和聊天记录里
跨部门靠人推一个项目要经过市场、研发、交付、财经，交接全靠沟通
进度看不见项目到了哪一步、钱收了多少，要翻表或者问人

背景 · 02

每条线，都按这 4 步走。

先听懂，再画清楚，再落到单据，最后才画页面。

  1. 交流访谈到对应部门，听他们现在怎么做、卡在哪里访谈
  2. 画出流程用泳道图画清：哪个部门、在哪一步、做什么泳道图
  3. 理出表单每个节点要填什么单、有哪些字段、谁来审批表单清单
  4. 设计原型把流程和表单变成页面，评审后交给开发Figma
流程访谈的部门画出的流程做成的系统模块
LTC 客户关系管理市场与客户管理部线索 → 签约 → 设计 → 采购 → 交付 → 收款市场管理、工单管理
IPD 产品生命周期管理研发管理部需求 → 立项 → 开发 → 测试 → 发布研发管理
ITR 客户服务管理项目交付部、研发管理部接收 → 分类 → 报价 → 处理 → 确认 → 收款售后管理
ISC 供应链与财务财经管理部（采购）供应商 → 采购 → 生产 → 交付 → 结算财经管理、库存管理

01

LTC · 客户关系管理

从一条线索，到一笔回款。

市场部牵头，研发、交付、财经接力。是四条线里最长的一条。

  • 市场与客户管理部
  • 研发 / 交付
  • 财经管理部

LTC · 01

先听市场部：一个客户是怎么跟下来的。

和市场部交流访谈，把他们日常的工作和卡点记下来，每一条都对应到系统里的一个做法。

访谈里听到的系统里怎么做
线索来源多：展会活动、电话咨询、老客户介绍线索统一登记，分配负责人，可以转成客户
客户跟进记在个人手里，换人就断了跟进记录挂在客户下面，谁跟的、聊了什么都留下
试用、方案、投标、成本测算，要找好几个部门签字统一用「工单」提单审批，进度在线上能看到
合同签了，回款什么时候到要去翻表合同关联回款计划，到期提醒
领导想看整体情况，要人工汇总销售简报：新增客户、商机、合同、回款一屏看到

LTC · 02

画出来：6 个阶段，一条主线。

泳道图按部门分列，每个节点右侧标出要用的表单。

  1. 线索与售前线索登记、客户拜访、项目评估、方案设计、成本测算
  2. 签约报价或投标、合同编制、合同评审
  3. 设计启动会、自主设计或委外设计、会签评审
  4. 采购采购申请、供应商合同
  5. 交付发货、签收、培训、验收
  6. 收款成本结算、收款

02

IPD · 产品生命周期管理

从一个想法，到一个产品。

研发管理部牵头。需求先进池子，评估通过才立项开发。

  • 研发管理部
  • 市场 / 交付反馈
  • 公司领导

IPD · 01

先听研发部：需求从哪来，怎么变成项目。

访谈里听到的系统里怎么做
需求来源很多：客户、市场、同行调研、交付反馈、公司战略所有需求进「研发需求池」，必须关联产品和负责人
需求提了没人回，不知道有没有在做新增需求提醒负责人，超过 3 天没评估再次提醒
标准产品、课题、售后问题，走法不一样流程分三条路：标准产品、课题研发、售后研发快速通道
项目进度和每个人手上的活看不清项目任务、甘特图、工时：按项目看，也能按人看

IPD · 02

画出来：5 个阶段，每段都有评审。

评审不通过就退回，通过才进入下一段。

  1. 需求管理收集需求、可行性分析评审
  2. 项目立项立项方案、立项评审、组建团队
  3. 设计开发方案设计、软硬件方案、采购、开发
  4. 测试验证测试用例、产品测试、测试评审
  5. 产品发布里程碑验收、发布评审、总结考评

03

ITR · 客户服务管理

客户报一个问题，到问题关闭。

项目交付部（售后）牵头。先分清是谁的问题，再决定怎么处理。

  • 项目交付部
  • 研发管理部
  • 市场 / 财经

ITR · 01

先听售后：问题怎么进来，怎么处理完。

访谈里听到的系统里怎么做
问题来源杂：客户反馈、市场、研发、交付现场统一登记「问题需求」，先回复客户「已受理」
有的是产品缺陷，有的是现场问题工作时间 1 小时内分类：研发问题转 IPD，交付问题走售后
收不收费、收多少，事后容易扯皮有费用先出报价单，客户确认后才处理
备件没库存，维修要等无库存直接发起采购申请，接到 ISC
处理完没有凭证服务报告签字确认，需要收款时发起售后收款

ITR · 02

画出来：两次判断，决定怎么走。

「谁来解决」和「要不要收费」是这条线上的两个关键分岔。

  1. 接收登记问题需求，回复已受理
  2. 分类研发问题 → IPD；交付问题 → 售后
  3. 报价产生费用时出报价单，客户确认
  4. 备件有库存直接用，没有就采购
  5. 处理自行更换、返厂、现场服务、远程更新
  6. 确认收款客户确认，需要时发起收款

ITR · 03

做成页面：售后管理。

一张仪表盘看清问题分布、超期提醒和维修金额。

超期提醒超过 3 天、7 天、30 天未处理，分档提醒

04

ISC · 供应链与财务

找供应商、采购，到付清每一笔款。

财经管理部牵头。各部门提资源需求，财经统一管供应商、采购和结算。

  • 财经管理部
  • 项目交付部
  • 各部门资源需求

ISC · 01

先听财经和采购：钱和货是怎么流的。

访谈里听到的系统里怎么做
供应商靠各部门推荐，好坏没有记录供应商推荐 → 考察 → 评分 → 考核，形成供应商台账
采购申请从各部门零散提上来采购申请统一入口，财经汇总成招采计划
采购方式不同，步骤也不同分成战略采购（询价）和招标采购两条路
项目做完，成本算不清交付后做项目成本结算，跟踪客户回款和供应商尾款

ISC · 02

画出来：从供应商到结算。

采购这一段最长，招标采购要经过公告、报名、评标、定标。

  1. 供应商管理推荐、考察、评分、考核
  2. 采购战略采购：询价比价；招标采购：公告、投标、评标、定标
  3. 生产预付款、供应商加工、物流跟踪
  4. 交付交付、供应商过程管理
  5. 结算项目成本结算、客户验收款、供应商尾款

系统 · 01

四条线不是孤立的，在系统里接上。

一条线的某个节点，会触发另一条线的开始。这些衔接点在画流程时就标出来了。

签约之后

市场启动单，自动生成交付计划。

自动生成市场启动单审批后，自动生成项目一体化计划和任务模板
多产品分批交付一个项目可以拆成多个产品，各自排期、各自看甘特图
超期标红实际工期超过计划工期，自动标红

系统 · 02

菜单按部门来分，不按流程来分。

每个人打开系统，先看到的是自己部门的事；流程在后台串起来。

市场管理线索、客户、商机、合同、回款、发票LTC
工单管理产品试用、售前方案、投标、成本测算、市场启动……LTC
研发管理研发需求池、研发项目管理IPD
生产管理装备生产、库存管理、售后管理ITR
财经管理供应商管理、采购管理、结算验收ISC
综合管理接待台账、用车台账综合
要审批的单 → 用「工单」有审批流、有状态、有提醒，跨部门协作都走工单。
只记录的表 → 用「台账」不需要审批的，比如接待台账、设备台账，用列表直接维护。

上线后

边用边改：收集问题，排优先级。

上线试用后，把大家反馈的问题按「重要 / 紧急」排序，一周一周地改。

网页端

  • 提交后马上能看到审批流工单增加「保存」和「提交」按钮，提交后立即确认审批流程
  • 详情页去掉无关内容只留和这张单有关的信息
  • 补上删除原来只能进详情页删，列表上加删除按钮
  • 工单按模板分类进菜单市场相关的工单归到一起，形成「市场管理」菜单

移动端

  • 审批要有通知移动端工单审批没有提醒，补上消息通知
  • 常用入口放第一位「全部应用」入口移到首位，全局统一配置
  • 少用的入口收起来办公、市场类入口按需要隐藏
  • 售后扫码报修设备贴二维码，扫码报修时自动带出设备交付信息

总结

流程先理清，系统才好用。

页面是最后一步。前面花时间听懂每个部门、画清每条线、理出每张单，画页面时才知道每个按钮为什么在那里。
