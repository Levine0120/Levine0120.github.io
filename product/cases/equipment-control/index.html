01 / PROJECT OVERVIEW

项目概述

两类界面，
分别服务操作与监测。

面向焊接、切割等设备，控制端承接现场操作和参数配置，监测端承接设备状态、数据及历史查询。产品围绕设备、任务和反馈建立关联。

B / DATA

数据分层

PRODUCT BRIEF / 业务与职责

解决什么问题，
为谁交付价值。

焊接、切割等设备同时存在操作控制与运行监测需求。产品需要将设备动作、参数和反馈对应起来，让现场人员知道正在控制哪台设备、指令是否执行、当前任务能否继续。

01

设备操作员

确认任务和加工对象，执行运行、暂停及复位等操作。

02

调试与工艺人员

设置动作和生产参数，检查设备反馈。

03

管理与运维

查看设备总览、运行记录、能耗及异常状态。

我的产品职责

负责接收设备业务需求，梳理动作、方向、角度、参数与返回信息，定义运行和调试流程；组织评审、跟进开发并在实际上位机中反复测试，推进验收、培训和问题修正。

CORE WORKFLOW / 核心业务链路

  1. 01确认设备与任务
  2. 02核对生产参数
  3. 03发起操作
  4. 04接收设备反馈
  5. 05处理异常
  6. 06记录完成情况

02 / CONTROL LAYOUT

主控界面

明确操作条件，
核对执行反馈。

先确认当前设备、连接及准备状态，再执行动作；参数和读数用于核对设备是否按预期响应。

COMMAND & FEEDBACK

请求与执行结果分开。

运行、暂停与复位分别定义可用条件；发出请求后以设备返回状态确认结果，连接异常时明确提示。

03 / PARAMETER RULES

参数规则

设置分组，
查看与修改分开。

根据现场作业与调试任务定义参数范围，区分查看和修改，明确名称、单位及适用设备。

01 / GROUPING

相关设置归组

按设备动作、生产条件和调试任务管理参数，明确它们共同作用的对象。

02 / INPUT

输入有依据

为每个参数约定名称、数据类型、单位与取值范围，越界和缺失值需要阻止提交并说明原因。

03 / MODE

区分查看与编辑

查看时不可误改参数；进入编辑后核对当前设备，保存结果需要与设备侧反馈一致。

HMI VARIATIONS

统一操作方式，
适用于不同界面。

运行、调试与生产设置分开呈现，顶部导航保持固定。

PRODUCT DECISIONS / 范围与规则

把需求拆清楚，
让取舍有依据。

围绕核心任务确定版本范围，再明确对象关系、状态含义与异常边界。

01

控制与监测分工

控制端服务当前设备的动作与设置，监测端支持跨设备总览和历史查询。监测状态不等同于可直接执行控制。

02

指令与结果分开

点击开始、暂停或复位只表示发出请求，执行状态以设备反馈为准；连接异常时避免把旧读数当作当前状态。

03

参数带上上下文

名称、单位、取值约束与适用设备一起定义，查看和编辑分开；动作可用条件需与设备侧逻辑对齐。

DELIVERY & ACCEPTANCE / 交付与验收

从需求评审，
到可验证的业务结果。

需求及原型评审→优先级与版本排期→研发跟进与联调→场景验收与问题复测→上线培训与反馈
01

实机操作

在上位机核查动作方向、参数生效、任务切换和控制反馈；异常与禁用行为按设备约束验证。

02

通信与读数

检查连接中断、反馈延迟、恢复连接和无数据；实时值与历史记录明确时间口径。

03

交付闭环

问题按设备、动作和复现步骤记录，与研发确认修正后复测；培训包含运行、调试和异常处理。

交付内容

需求清单与版本范围 · 业务流程与原型 · 字段及状态说明 · 评审记录 · 验收场景与问题清单 · 上线说明与迭代事项

ITERATION / 复盘关注

上线之后，
继续跟进使用中的问题。

01

操作问题

归类误选对象、参数理解偏差和反馈不明确的问题。

02

运行问题

追踪故障、停机与连接异常，区分软件流程和设备侧原因。

03

后续版本

优先处理阻塞作业及状态不一致，再完善跨设备统计与查询。

以业务记录和使用反馈为依据，持续调整版本优先级。

08 / DELIVERY PROCESS

交付过程

从现场需求，
到实机验证与迭代。

先整理动作、参数和返回信息，再与研发对齐实现规则；上线前在实际设备上走查，问题修正后复测。

交付阶段设备操作 · 控制界面运行监测 · 数据看板

调研动作、参数和可用条件。

02组织

评审任务流程与状态规则。

对齐总览与单机查询范围。

03设计

跟进开发，验证查看和编辑。

联调设备反馈与历史记录。

04校对

实机验收、培训并复测问题。

上线核对口径并跟进反馈。
